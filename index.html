Contract triage queue

The brief described a legal team reading every contract the same way regardless of risk. I designed a queue that sorts contracts by how much attention each one needs.

Full reviewReview and respondCleared to sign
  • Unfamiliar first. Clauses the written rules don’t cover sit at the top, each summarised in one plain sentence.
  • Findings open in place. Show in contract scrolls the full document to the clause and marks the exact wording.
  • Colour means something. Acceptable changes are green, not red, so the reviewer never learns to ignore the colour.
What I did

Turned the brief into the flow and screens, wrote the spec for all sixteen versions, directed the build with Claude Code and reviewed each one in the browser.

What testing taught me

Reading the output is how I caught “forty-five days” being read as five days, which silently put a contract in the wrong lane. It is now a permanent test.

Lantern Studio

Lantern turns a written script into a finished documentary for my channel, Defiant. Lantern Studio is the browser workspace I designed for reviewing every shot before export.

  • Script in view. It stays on the left, so footage is judged against the line it illustrates.
  • Compare, then approve. The generated and upscaled clips play side by side, which is why I rebuilt it for the browser.
  • State always visible. A status line counts what is selected, queued, running, done and failed.
What I did

Wrote the specification and interface rules, directed the build with Claude Code, and review every episode in it.

What testing taught me

The desktop version dropped the 480p clip when upscaling and let requests fail silently, so the browser one keeps both clips and says plainly when something cannot run.

LinkUp

Turns vague group chat plans into real events. Each event gets its own card, RSVPs and photos, then becomes a shared memory. I took it from first sketch to release candidate.

  • A written design system. One set of rules for palette, type, spacing, 44 pixel touch targets and motion.
  • Phase colours. Planning, coming up, live and memory each get their own, so a plan’s progress reads at a glance.
  • Every state designed. Skeletons while loading, empty lists with a next step, and inline validation instead of alerts.
What I did

Designed the flows and the design system, specified each stage, directed the build with Claude Code and checked it screen by screen in the app.

What testing taught me

When a group icon upload failed silently on a preview build, I had the raw error shown on screen and reproduced it on the device before changing anything.
